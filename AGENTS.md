# ЛХЛ-76: работа с исходниками и Git

Публикация временно приостановлена по просьбе пользователя. Не выполняйте
`git push` ни в один удалённый репозиторий, пока пользователь явно не разрешит
возобновить отправку.

После возобновления публикации пользователь разрешил автоматически отправлять
каждую завершённую и проверенную доработку исходников в приватный проект GitFlic
`https://gitflic.ru/project/andy410/lhl76-site`. Делайте коммит и
`git push gitflic main` без отдельного запроса для каждой доработки. Не
отправляйте незавершённые или заведомо неработающие изменения. GitHub remote
`origin` сохранён как прежнее место публикации; не пушьте туда без прямого
указания пользователя.

В локальном комплекте `D:\LHL76-Project` папка `source/` — действующий проект
с локальной базой, секретами и старой историей Git. `publish-source/` — чистый
Git-репозиторий для публикации исходников. Работайте с проектом в `source/`,
а для публикации переносите изменённые файлы исходников в `publish-source/`,
включая удаления. Никогда не пушьте старую историю из `source/.git`. В другом
клоне работайте непосредственно в его Git-репозитории.

В удалённый репозиторий должны попадать только исходники: `src/`, `prisma/`, `scripts/`, `docs/`,
`public/images/` и файлы конфигурации в корне проекта. Проверьте список файлов
перед каждым коммитом. Не копируйте `.env.local`, действующие секреты,
`database/`, дампы, `public/uploads/`, `public/legacy-media/`,
`public/documents/`, логи, резервные копии, `node_modules/` и `.next/`.
Файл `.env.example` допустим; SQL-миграции в `scripts/migrations/` — исходники.

После push проверьте SHA удалённой ветки и укажите ссылку на репозиторий и хеш
коммита в ответе. Если авторизация или push не сработали, сохраните локальные
изменения и сообщите, что отправка не выполнена.
