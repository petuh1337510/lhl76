# ЛХЛ-76: работа с исходниками и Git

Публикация исходников и развёртывание выполняются только через GitHub
`https://github.com/petuh1337510/lhl76` (аккаунт petuh1337510).
GitFlic больше не используется. Старый GitHub origin также не используйте.
Пользователь разрешил автоматически отправлять каждую завершённую и проверенную
доработку в main этого репозитория без отдельного запроса. Не отправляйте
незавершённые или заведомо неработающие изменения. Если пользователь для
конкретной задачи попросил не пушить, следуйте этому указанию.

В локальном комплекте `D:\LHL76-Project` папка `source/` — действующий проект
с локальной базой, секретами и старой историей Git. Работайте с проектом в
`source/`. Для публикации переносите только изменённые исходники, включая
удаления, в чистый checkout актуального main `petuh1337510/lhl76`.
`publish-github/` — checkout истории GitHub; `publish-source/` содержит прежнюю
историю GitFlic, не отправляйте её в GitHub. В текущем checkout используйте
`git push github-petuh HEAD:main`, предварительно проверив remote и историю.
Никогда не пушьте старую историю из `source/.git`. В другом клоне работайте
непосредственно в его Git-репозитории.

В удалённый репозиторий должны попадать только исходники: `src/`, `prisma/`, `scripts/`, `docs/`,
`public/images/` и файлы конфигурации в корне проекта. Проверьте список файлов
перед каждым коммитом. Не копируйте `.env.local`, действующие секреты,
`database/`, дампы, `public/uploads/`, `public/legacy-media/`,
`public/documents/`, логи, резервные копии, `node_modules/` и `.next/`.
Файл `.env.example` допустим; SQL-миграции в `scripts/migrations/` — исходники.

После push проверьте SHA удалённой ветки и укажите ссылку на репозиторий и хеш
коммита в ответе. Если авторизация или push не сработали, сохраните локальные
изменения и сообщите, что отправка не выполнена.
