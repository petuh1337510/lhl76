# Фотоальбомы VK

Источник — публичные альбомы https://vk.ru/lhl76. Администратор выбирает альбомы в /admin/media; новые альбомы выключены. Существующие локальные альбомы остаются доступны отдельно. На сайте используется прежний адрес /media, теперь с названием «Фото».

## Подключение

В GitHub откройте Settings → Environments → production → Environment secrets и добавьте VK_API_ACCESS_TOKEN. Затем запустите Actions → Build and deploy LHL-76 → Run workflow для main. Workflow передаёт ключ в закрытый runtime.env сервера и окружение контейнера app; не вставляйте ключ в исходники. При каждом следующем развёртывании секрет берётся из этого же Environment. Используйте подходящий пользовательский или сервисный ключ приложения: photos.getAlbums и photos.get не принимают обычный ключ сообщества. Не записывайте ключ в репозиторий. Проверка подключения — успешное получение списка в /admin/media и открытие выбранного альбома. Наличие переменной само по себе не подтверждает права ключа.

Схема методов VK: https://github.com/VKCOM/vk-api-schema/blob/master/photos/methods.json

## Обновления и хранение

В БД сохраняются выбранные альбомы и начальные сведения/URL, в Next Data Cache — последние успешные ответы API. Изображения загружаются браузером напрямую из VK, без Next Image Optimization и /api/public/remote-image. Собственных копий файлов нет.

Ответы API обновляются примерно раз в час (stale-while-revalidate). В постоянно работающем Node-сервере фоновая проверка каждую минуту поддерживает обновление выбранных альбомов; одновременно выполняется только один проход. В среде, приостанавливающей процесс, обновление возобновится при запросах. «Обновить сейчас» сбрасывает кэш группы и фотографий; следующий просмотр получает свежие данные.

Только успешный полный список группы позволяет скрыть отсутствующий альбом. Явный отказ доступа к альбому также скрывает его. Выбор публикации не сбрасывается, поэтому вернувшийся альбом появляется автоматически после обновления. Сетевые ошибки, ограничения API и проблемы авторизации не считаются удалением. Пустой успешный список фотографий заменяет старый список. Обновление одного альбома не загружает фотографии всех остальных.

Без рабочего ключа интерфейс показывает ошибку настройки. До настройки реальный обмен с VK и доступность его CDN проверить нельзя. Миграция БД не требуется.

При обновлении deploy-release.sh разрешает изменение только образа приложения и VK_API_ACCESS_TOKEN. Проверки неизменности остальных настроек, базы и медиа сохраняются. При неудаче восстанавливаются прежние runtime.env и Compose.

Перед завершением релиза выполняется проверка utils.resolveScreenName, photos.getAlbums и (при наличии альбома) photos.get из контейнера приложения. В журнал попадают только количество альбомов/фотографий или безопасный код ошибки. Если заданный ключ не работает, релиз откатывается; базу и медиа откат не затрагивает.
