# Импорт JoomSport

Источник пилотного переноса — фактический SQL-дамп старого WordPress/JoomSport. Импорт выполняется по цепочке **extract → transform → validate → import → verify**, поддерживает `dry-run`, журнал аномалий и соответствия `старый ID → UUID`.

## Как трактовать старый список «сезонов»

JoomSport называл отдельным сезоном каждый дивизион каждого соревнования. В новой системе эти записи нельзя переносить как семь самостоятельных сезонов.

Правильная структура данных 2023/24:

```text
Сезон 2023/24
├── Чемпионат ЛХЛ-76
│   ├── Любитель Спорт
│   ├── Любитель Плюс
│   └── Любитель
├── Турнир «Апрельский 2024»
│   ├── Любитель Плюс
│   └── Любитель
└── Турнир «Памяти Локомотива 2023»
    ├── Любитель Плюс
    └── Любитель
```

Название и год соревнования объединяют старые записи, а подпись в скобках становится дивизионом.

| Старый ID | Новое соревнование | Новый дивизион |
|---:|---|---|
| 2220 | Чемпионат ЛХЛ-76 | Любитель Спорт |
| 2476 | Чемпионат ЛХЛ-76 | Любитель Плюс |
| 2477 | Чемпионат ЛХЛ-76 | Любитель |
| 3029 | Памяти Локомотива 2023 | Любитель Плюс |
| 3026 | Памяти Локомотива 2023 | Любитель |
| 6780 | Апрельский 2024 | Любитель Плюс |
| 6781 | Апрельский 2024 | Любитель |

## Карточка игрока

Из общей карточки JoomSport переносятся:

- фамилия, имя и отчество;
- имя в родной стране;
- дата рождения, страна и место рождения;
- амплуа и хват;
- рост и вес;
- квалификация с историей по сезону;
- лига;
- основная фотография;
- фото и достижения лауреата.

Старое поле «Статус» не переносится.

Игровой номер, капитан и ассистент не являются постоянными свойствами игрока. Они переносятся в `RosterEntry` — конкретную заявку игрока за конкретную команду, дивизион и соревнование.

## Границы данных

Каждая выборка состава, календаря и статистики должна проходить через полную связь:

```text
Season → Competition → Division → TeamEntry → RosterEntry
```

Это позволяет одному игроку одновременно выступать в разных командах и дивизионах одного соревнования и не смешивает заявку чемпионата с заявкой турнира.

Матчи обязательно получают стадию. Только стадия с `countsForStandings = true` участвует в турнирной таблице. Для чемпионата 2023/24 это групповой этап; четвертьфиналы, полуфиналы, финалы и матчи за третье место в таблицу не входят.

## Повторяемый импорт

`LegacyImportMap` хранит источник, тип объекта, старый ID и новый UUID. Благодаря этому повторный запуск обновляет уже перенесенные объекты и не создает дублей.

Порядок пилота:

1. Сезон, соревнования и дивизионы.
2. Команды и единые логотипы.
3. Игроки и единые фотографии.
4. Заявки команд и игроков.
5. Стадии, площадки и матчи.
6. Составы на матчи, голы, передачи и штрафы.
7. Пересчет таблиц и статистики.
8. Сверка количеств и ручная проверка аномалий.

Подробные результаты первичного анализа находятся в `docs/LEGACY_2023_24_AUDIT.md`, а итог полного безопасного прогона всего сезона — в `docs/LEGACY_2023_24_DRY_RUN.md`.

Фактический результат успешной загрузки в тестовый PostgreSQL находится в `docs/LEGACY_2023_24_IMPORT_RESULT.md`.

Повторить полный прогон без записи в базу:

```powershell
pnpm legacy:dry-run -- "C:\Users\USER\Downloads\lhlnew.sql" --dry-run
```

## Транзакционный импорт в тестовую базу

Импортёр подготовлен, но намеренно не запускается без трех одновременных условий:

1. передан флаг `--commit`;
2. имя базы в `DATABASE_URL` содержит `test`, `import` или `staging`;
3. установлено точное подтверждение `LEGACY_IMPORT_CONFIRM=2023-24`.

Пример для отдельной тестовой базы:

```powershell
$env:DATABASE_URL="postgresql://lhl76:lhl76@localhost:5432/lhl76_import_test?schema=public"
$env:LEGACY_IMPORT_CONFIRM="2023-24"
pnpm exec prisma db push
pnpm legacy:import -- "C:\Users\USER\Downloads\lhlnew.sql" --commit
```

Вся загрузка и контрольная сверка выполняются внутри одной транзакции. Если количество хотя бы одного вида объектов не совпадает с планом, транзакция отменяется целиком. Повторный импорт того же источника также блокируется через `LegacyImportMap`.

Без `--commit` команда строит только нормализованный план и ничего не записывает:

```powershell
pnpm legacy:import -- "C:\Users\USER\Downloads\lhlnew.sql"
```
