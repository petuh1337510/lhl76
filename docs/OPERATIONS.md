# Эксплуатация и восстановление

## Что будет контролироваться

- доступность сайта через `GET /api/health`;
- доступность PostgreSQL;
- успешность ежедневного резервного копирования;
- свободное место диска и ошибки приложения.

Мониторинг будет обращаться к `https://ваш-домен/api/health` раз в 1–5 минут и отправлять уведомление ответственным, если сайт не отвечает.

## Резервные копии

После размещения сайта на хостинге настраиваются ежедневные дампы PostgreSQL и хранение минимум 14 последних копий **вне сервера приложения**. Раз в квартал выполняется тестовое восстановление на отдельной базе.

Никогда не восстанавливайте базу «поверх» работающей версии без свежего резервного снимка. Сначала фиксируются время сбоя и логи, затем поднимается последняя целая копия или применяется точечное исправление.

## При сбое

1. Проверить `/api/health`, логи приложения и состояние PostgreSQL.
2. Проверить свободное место и параметры подключения к БД.
3. При необходимости развернуть приложение из Docker-образа той же версии.
4. Восстановить БД только из проверенного резервного дампа.
5. Проверить матчи, протоколы и таблицы после восстановления.

Доступ к серверу, панели хостинга и хранилищу резервных копий остаётся у лиги. Без такого доступа невозможно безопасно устранить инфраструктурную проблему.
